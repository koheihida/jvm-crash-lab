# jvm-crash-lab

「ピュアJavaでJVMをクラッシュさせられるのか？」を、再現可能な実験を通して検証する研究プロジェクトです。

『情熱プログラマー』に着想を得て、JVMの異常終了、バイトコード検証、JITコンパイルなどの境界を段階的に調査します。最終的な成果物として、技術ブログの執筆とカンファレンス登壇を目指します。

## Research question

Javaで記述されたプログラムから、JNIなどのネイティブコードを直接利用せずに、JVM自身の異常終了を引き起こせるのでしょうか。

この問いに答えるため、Javaアプリケーションの異常終了とJVM自体のクラッシュを区別したうえで、各現象の再現条件と限界を調査します。

## Scope

本プロジェクトにおける「ピュアJava」の厳密な定義は、研究の初期段階で整理します。現時点では、次の条件を暫定的な出発点とします。

- 実験コードをJavaで記述する
- 標準のJavaランチャーから実行する
- JNI、JNAなどのネイティブコード呼び出しをクラッシュ手段として使用しない
- 外部プロセスからのシグナル送信や強制終了をクラッシュ手段として使用しない
- バイトコードの生成や操作は、それ自体を独立した研究対象として扱う

境界的なAPI、JVMオプション、外部ライブラリの扱いは、実験ごとに明示します。

## Research areas

以下の順序で調査を進めます。

1. JVMの異常終了と「クラッシュ」の定義
2. `StackOverflowError` の挙動
3. Javaからのバイトコード生成・操作
4. Bytecode Verifierの役割と限界
5. JITコンパイラの挙動
6. 再現性の確認と結果の整理

## Environment

現在の基準環境は次のとおりです。

- macOS 26.6.2（Build 25G83）
- Apple Silicon ARM64
- Microsoft OpenJDK 25.0.5.1 LTS
- OpenJDK 64-Bit Server VM（mixed mode, sharing）
- `javac 25.0.5.1`
- Git 2.40.1

実験結果には、実行時の環境、JVMオプション、終了コード、標準出力、標準エラーを記録します。

## Research principles

- 仮説、観測、推論、結論を区別する
- 実行していない実験の結果を書かない
- 成功だけでなく、失敗、反証、再現不能も記録する
- 結論には再現手順と根拠となる出力を添える
- 特定のJDKや環境で得た結果を、JVM全般の事実として一般化しない
- 学習と検証の過程をGit履歴に残す

## Status

研究基盤を整備しています。JVMクラッシュに関する実験はまだ実施しておらず、現時点で確定した実験結果はありません。

## Safety

このプロジェクトでは、JVMの異常終了、スタックやメモリの消費、大量のログ生成などを意図的に検証する可能性があります。

実験は本番環境で実行せず、対象コマンド、想定される影響、停止方法を確認してから実施します。
